# Character sets

Find accepts one character-set filter at a time. An empty query browses its mapped characters, 240 to a page; a query intersects the set with every result channel. On a screen 1200 pixels wide or more, a browsed page also lays its rows one value of the code's last digit wide: sixteen for a hexadecimal index and ten for a decimal one, so the grid turns like the source's own code table. A narrower screen keeps the auto-fill grid. The address stores the selection in `?set=`, alongside `?q=`, `?c=` and the browsed page in `?p=`.

A browsed character carries the code its own set gives it, printed under the glyph. The code is the source's index — a CNS grid position such as `1-4421`, a kuten position, a code point or a serial. It is not a scalar assignment. The grid can follow that code order instead of code-point order, and can show only members with an assigned scalar or only private-use slots and other unencoded forms. A second filter narrows the grid to Han characters; private-use slots stay, since they stand for Han records without a scalar.

A member is a string of one or more code points. GB 12052 writes 1,718 archaic Hangul syllables as two or three jamo, which the grid draws as one syllable block; the rest of the catalogue's members are single scalars. Browsing a standard's table can therefore show characters the finder does not search, such as its symbols and Hangul.

Each set has a unique character count and a source-row count. A source row joins through its assigned scalars, or through its private-use glyph slot where no scalar is assigned. A row whose only glyph is an Ideographic Description Sequence stays out of the scalar count and is kept as a record on the set. Repeated mappings, variation sequences and IDS descriptions can make the counts differ. Draft row numbers never establish Unicode assignments.

A selected set also shows its source coverage: `encoded` counts source characters that resolve to assigned Unicode code points, whether one scalar or the jamo sequence a member is made of, including characters outside the search scope. It counts distinct glyphs for 字統 and Ext.E, and rows for CNS. `unencoded` counts rows without such an assignment, including IDS descriptions and private-use slots. Repeated 字統 scalars and variation sequences are not counted, so the two totals need not add up to the source-row count. `chars` remains the browsable count, which includes CNS private-use slots, and IWDS `total` counts entries rather than its example characters. Catalogue pies mark sets with unencoded rows, and their title gives the exact numbers.

Where the catalogue records a designed code space, the coverage dial divides by it: GB/T 12052 by its 94×94 cells and a Unicode block set by the block's range. Filled positions that carry a scalar, filled positions without one, and unassigned cells each take a segment, so GB/T 12052 reads 5,977 in Unicode, 2 unencoded and 2,857 unassigned of 8,836. Other sets divide by their characters.

**Compare with** intersects the two sets' listed characters. The overlap pie shows the characters in both and the characters only in the selected set; the percentages are of the selected set's listed characters and of the other set's. A 字統 row without an assigned scalar is absent from the set's listed characters, so it cannot be compared, while a CNS private-use slot matches only the same slot. A set with printed records counts its records instead: shared records, mapped records only in the selected set, and records without a scalar each take a segment, and the hint gives the printed records that cannot enter the comparison.

The panel groups every source character of the selected set by Unicode block: URO, Ext.A through Ext.J, the two compatibility blocks, Basic Latin, the kana blocks, the radical and stroke blocks, Nushu, Other for anything else, and 未編碼 for records without a scalar. Each share divides by the set's distinct listed members with a scalar plus the catalogue's unencoded record count, so a private-use slot appears once, in the 未編碼 row. The ranges come from Blocks.txt 18.0.0. A version list below the blocks gives the Unicode version that first assigned each character, with its count and share; a version spread over one or two code point runs also shows those ranges. DerivedAge 18.0.0 supplies the version, so the list describes Unicode assignment rather than the set's source document; a member made of several code points counts under the last of them to be assigned. Ranges follow the selected set's members, so an editorial substitution can split a version's range. Unencoded records close the version list as one row and take one chip in the planes line. The same ranges give each CJK block's assigned code points; the block occupancy table shows the empty count and its share of the block's code points, so a nearly full block reads as Ext.D with 1 empty of 224. A planes line gives the selected set's share in planes 0–3 (BMP, SMP, SIP, TIP); characters above plane 3 are grouped as Other. Each of the three groups draws its shares as a pie whose slices follow the list. The coverage dial and each group print the denominator they divide by.

Sets with unencoded rows link to their records; 50 字統網 sets carry IDS descriptions this way. Proposal sets with unencoded forms link to their source rows.

## CNS source categories

The **CNS source categories** shortcut opens the source list without choosing a character first. Categories include 常用國字標準字體表、次常用字國字標準字體表、罕用國字標準字體表、異體國字字表、戶政、地政、財稅、工商登記、文獻 and local-language collections. Edition qualifiers remain part of each exact source label.

`CNS_source.txt` records the source at registration for each CNS code. The catalogue lists every source row: an assigned scalar is browsable as that character, and a row with only a private-use mapping is browsable as its PUA-A glyph slot, drawn from its IDS by han-compose where one is recorded and otherwise by the bundled TW-Sung-Plus slice. Unihan 18 `kIRG_TSource` supplies scalars assigned after the bulk release (TB-7D29 is U+324D6), while the row keeps its earlier private-use mapping. The bulk release is dated 2026-08-05; individual pages on the live CNS site can contain later changes.

CNS plane numbers in these files are decimal. Source categories, planes and historical provisional status have separate meanings. The source table has no Extension E withdrawal category.

## Printed proposal records

A proposed character that was never encoded has no scalar, so its set cannot be a list of characters. The proposal sets keep the printed record instead: the codes printed beside each glyph, and the glyph cut from the document's page. Records the documents explain without a glyph stay text-only, and a record with a verified correspondence links to that character's card. The record grid prints each code under its glyph, can follow the printed code order, and can show only records with a verified correspondence or only those without one.

`bun scripts/import_irg_records.mjs` reads each pinned PDF with poppler's `pdftohtml`, which gives text and image boxes in one coordinate system. `scripts/sources/irg.mjs` pairs every glyph with the codes beside it: a serial stacked over its source (IRGN1531, IRGN1841, IRGN1330) or beside it (IRGN1925), one line of two codes (IRGN1250), or a serial and draft code point in one cell with the source beside it (IRGN1567). A table without glyphs reads a row number and working number in one cell with the source in the next column (IRGN1306). A prose list prints its ids as tokens, read in printed order until the paragraph that opens the next list (IRGN424). A running list can print its glyph as private-use text instead of a stencil (IRGN1525); that glyph is cropped from a rendering of the page. ImageMagick then draws the strokes black on a transparent ground, since the documents use both polarities. A set is written only when its record count matches; glyph rows must have distinct serials, and sources must be distinct unless the step allows a document's repeats. IRGN1306 has no glyph rows and repeats one working number and two sources, which its step accepts rather than dropping rows. Regenerating needs poppler and ImageMagick.

These are proposal numbers, not scalar assignments. IRGN1841 lists characters for withdrawal while leaving later resubmission possible; IRGN1250 removes J sources from the CJK D candidate for lack of evidence, and some of its characters were proposed again.

## ebag glyphs

GlyphWiki's `ebag_*` names are the 缺字編號 that 引得市 uses for its missing-character index. The set keeps 24,359 records, each the glyph name and a link to its GlyphWiki page; 24,356 render from the dump's KAGE data as sprite sheets, and three keep the name only because two recurse through their components and one has degenerate stroke data.

`bun scripts/import_glyphwiki_ebag.mjs` reads the pinned dump and writes the records; the dump's SHA-256 is in `glyphwiki_ebag_source.json`. `python scripts/build_ebag_sprites.py` renders the sheets; it needs the KAGE engine (GPL-3.0) installed separately. The glyphs are not scalar members: the set counts zero characters and 24,359 unencoded records, and GlyphWiki's related character is not treated as an assignment.

## CBETA missing characters

CBETA keeps a CB code and a composition formula for each missing character (缺字) in its texts. The set lists every code, and the 271 codes the image archive has without a database row. A code with a Unicode character is a member, browsable with its CB code printed under it; the rest are records. The record grid draws CBETA's glyph, or the Unicode character where CBETA has no image. A record card shows CBETA's glyph, the formula and the IDS the general arithmetic notation gives for it (31,451 of 31,664 formulas parse), CBETA's similar Unicode character and Big5 common form where it gives one, and a link to the Ministry of Education's variants dictionary. A workbook adds the radical, stroke count and zhuyin CBETA's web pages give, an IDS for 3,672 unencoded codes, a machine conversion of the formula for 4,747 (2,255 of them without the workbook's IDS), and a Unicode character proposed for 608 codes CBETA leaves unencoded beyond its own similar character and common form. These stay in each record's `workbook` field, and the card shows them in a block headed by the workbook's name. A stroke note that counts the radical negatively (`5=-8+13`) is dropped.

Find searches the unencoded records alongside the characters. A record matches a part its formula or either IDS keeps, in any of the part's written forms (氵 for 水); a part the formula subtracts or replaces does not count. It also matches the workbook's stroke count, a zhuyin reading with or without tone, or a character a source relates it to (CBETA's similar character and common form, the workbook's proposed character). Several clues keep the records that match all of them. A set opts in with `records.search` in the catalogue; CBETA is the only one.

`uv run scripts/import_cbeta_gaiji.py` reads the pinned database and image archive, whose digests are in `cbeta_gaiji_source.json`. It fits each glyph to a 64-pixel cell and packs 256 to a one-bit PNG sheet under `cbeta-glyphs/`. The 271 image-only codes follow the database's codes on the sheets, so adding them left the earlier sheets unchanged. 172 database codes without a Unicode character have no image. CBETA's similar character looks close to the CB glyph without being the same, so it is not counted as an assignment. CBETA reserves U+F0000 plus the code's number as each code's private-use slot. The range overlaps the CNS 全字庫 slots, so the two stay separate schemes: Find reads a slot in each, and the converter takes one scheme at a time or reports the conflict.

## FZ private-use table

Four 方正超大字符集 fonts define 633 distinct BMP private-use slots: 522 in FZKTJW, 122 in FZSongS, 108 in FZJiaoCai GuiFanKai and 106 in FZKTK, with 106 slots shared by at least two faces. The set lists each slot and the faces that define it; no slot is treated as a coded character, and the font files and glyph outlines are not kept.

The public copies are unofficial. `uv run --with fonttools python scripts/build_fz_pua.py` fetches the six files from a pinned commit of the mirror into `cache/fz-fonts/`, reads their cmaps and writes the records; each file's digest is in `fz_pua_source.json`. None of the six files has a plane-16 mapping, so 字統's `G方正楷体` plane-16 table is not reconstructed.

## Dialect characters

Each set holds the characters one doculect coined or gave its own use. Characters shared with the standard written language stay out, so a set takes only a source's dialect-specific tier.

The twelve Chinese sets follow the 嚴式方言字 list of the 全國漢語方言用字總表: 官話, 晉語, 吳語, 徽語, 贛語, 湘語, 客家話, 粵語, 閩語, 閩東語, 閩南語 and 平話. A row joins every group it is labelled with. The list labels Min only as 閩; 閩東語 takes the Min rows it reads at Fuzhou or Gutian, and 閩南語 those it reads at Xiamen, Zhangzhou or Zhangping. Its 寬式方言字 tier, ordinary characters such as 乞 or 比 given a dialect sense, stays out. 日本國字 and 朝鮮國字 take the kokuji and gukja groups of IDS Workshop's open IDS descriptions. A row that the source can only describe with an IDS is a record on its set.

`bun scripts/build_dialect_chars.mjs` rebuilds the sets from the inputs pinned in `dialect_source.json`; the full build calls the same writer.

## Study headword tables

Twenty-six sets index the headword (字頭) tables compiled from research books on 疑難字, 俗字 and 異體字, one set per book, in the group 研究字頭. An encoded headword is a member, with the book's own locator under it. A headword written as an IDS, a component description or a private-use character is a record that Find reaches through its parts.

A record's source is the locator the book prints: a page, a page-column such as `359-1`, a serial, or a volume and serial. A record may also list related characters, the forms a table gives side by side, and alternate forms. A record's card links the related characters and names the kind of relation where the table does.

Related forms come from the 随函录 correct-form column, the 简化汉字修订方案 同字 column, the 甲骨文字释林 或作 column, the rows of several forms in 正字通, 隋唐墓志, 一切经音义 and 东汉碑刻, the pairing of 康熙外字 forms with their stand-in characters, and the brackets of 疑难字简明字典 (（） simplified, ［］ variant, 〔〕 jump). Section headings, multi-character words and placeholders are dropped, and an identical headword on the same page is kept once.

`uv run scripts/import_study_tables.py` reads the tables from `cache/study-tables/`, checks each against its SHA-256 and writes `study_*_records.json` and `study_*_source.json`; the full build indexes them.

## G source collections

Thirteen sets index the G source codes that name publications and lists in Unihan `kIRG_GSource`: GDM, GHC, GKJ, GLGYJ, GPGLG, GXM, GZ·U and GZA-1, -2, -3, -4, -6 and -7. A member is an assigned character whose value carries the code; no unencoded row enters these sets. The code under a member is that member's G source serial, such as GDM-00013. The GZA sets split on the serial's first digit, the `[123467]` of UAX #38's `GZA-[123467]\d{5}` pattern, so GZA-5 has no members. GZ·U holds the encoded GZ source; the existing gz set is 字統's broader snapshot of the 古壯字字典, with 7,964 rows including unencoded forms, and keeps its label.

The counts follow Unicode 18.0.0. The [Chinese Wikipedia table for Extension H](https://zh.wikipedia.org/wiki/中日韓統一表意文字) lists that block's counts under Unicode 15.0, such as GDM 128 and GZ 285; later Unihan revisions moved characters between G sources, so a whole-source set counts more. UAX #38 supplies the category names and the six GZA titles.

## G source labels

Character cards show the G source beside its code, and a printed record card does the same; the record grid puts the source under the glyph and in the tile title. The glossary lists GCH 辭海, GCYY 中國測繪科學研究院用字, GBK 中國大百科全書, GJZ 商務印書館用字, GZFY 漢語方言大詞典, GH GB/T 15564 and GKX 康熙字典; a code outside these stays plain. The code stays text; the source name opens a note with the edition or institution. The notes live in [sources.js](../app/lib/sources.js). [UAX #38](https://www.unicode.org/reports/tr38/#kIRG_GSource) defines the codes and the edition behind GCH; the institutional dates come from [CASM](https://www.casm.ac.cn/chbyjj/chyjj/index.html), the [Commercial Press](http://cpem.cp.com.cn/home/aboutcpem) and [Cihai](https://www.cihai.com.cn).

## Data and checks

The checked-in [catalogue](../app/public/charsets/index.json), per-set text files, `.codes.tsv` files and [source digests](../app/public/charsets/sources.json) work without requests to external services. Each member file has one member per line, so a jamo sequence stays one member. Each code file has one `character<TAB>code` line for each member the source gives a code, in the set's source order; the catalogue's `codes` field points to it. A member without a source code keeps no line. `bun scripts/build_charset_codes.mjs` refreshes those files from the pinned payloads in `cache/` without refetching the catalogue. The generator checks downloaded bytes, and the digests an importer pins in its `<id>_source.json`, against recorded SHA-256 values. Source files are cached under `cache/`; changed inputs require a reviewed digest update.

```sh
bun scripts/import_irg_records.mjs
bun scripts/import_glyphwiki_ebag.mjs
uv run scripts/import_cbeta_gaiji.py
uv run scripts/import_study_tables.py
bun scripts/build_charsets.mjs
bun scripts/build_g_sources.mjs
bun scripts/build_dialect_chars.mjs
bun run verify
bun run build
bun scripts/check_charsets.mjs
```

`bun scripts/build_g_sources.mjs` refreshes the thirteen G source sets from the pinned Unihan bytes without rebuilding the 字統 catalogue; the full build calls the same writer. The browser check serves the built distribution through Playwright request routing, so it requires no preview server. It covers selection, browsing, every search channel, URL history, stale requests, failures, retry, keyboard focus and both themes at desktop and phone widths. Screenshots are written under `shots/`.
